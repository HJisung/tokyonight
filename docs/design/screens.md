# 화면 구성

MVP 화면의 배치와 단축키입니다. 색·글꼴·간격은 [`DESIGN.md`](../../DESIGN.md), 제품 사실은 [`PRODUCT.md`](../../PRODUCT.md)가 기준입니다.

T-010에서 실제로 만든 것은 **뼈대**(위쪽 줄, 사이드바, 본문 영역, 사이드바 접기·너비 조절, 테마 전환)뿐입니다. 각 영역의 내용은 아래 표의 task가 채우며, 이 문서의 와이어프레임은 그 task들이 따를 배치 제안입니다. 사용자 검토는 MVP 완성 뒤에 받습니다.

## 뼈대

```
┌──────────────────────────────────────────────────────────────────┐
│ [◧]  워크스페이스 탭 줄                                       [◐] │  위쪽 줄
├───────────────┬──────────────────────────────────────────────────┤
│               ┃                                                  │
│   사이드바     ┃                    본문 영역                      │
│               ┃                                                  │
│               ┃                                                  │
└───────────────┴──────────────────────────────────────────────────┘
                ↑ 경계선(끌어서 너비 조절)
```

| 영역 | 역할 | 채우는 task | 코드 |
| --- | --- | --- | --- |
| 위쪽 줄 | 사이드바 접기 버튼 `[◧]`, 워크스페이스 탭, 테마 전환 `[◐]` | T-041 (탭) | `AppShell`의 `tabs` |
| 사이드바 | 열린 폴더의 파일 목록 | T-023 | `AppShell`의 `sidebar` |
| 본문 영역 | 시작 화면, 문서, 분할 영역 | T-022, T-024, T-040 | `AppShell`의 `children` |

배치 결정(가정, 사용자 검토 전):

- **위쪽 줄은 창 너비 전체를 차지합니다.** 사이드바를 접어도 접기 버튼이 같은 자리에 남고, 탭이 많아져도 줄을 가장 넓게 쓸 수 있습니다. 탭을 바꾸면 본문만 바뀌고 사이드바의 폴더와 파일 목록은 그대로입니다. 대안은 사이드바가 창 높이 전체를 차지하고 탭 줄이 본문 위에만 놓이는 배치입니다.
- **사이드바**: 기본 너비 264px, 200~480px 사이에서 조절합니다. 경계선을 끌거나, 경계선에 포커스를 두고 `←` `→`(16px씩), `Home`(최소), `End`(최대)로 바꿉니다. 경계선을 두 번 누르면 기본 너비로 돌아갑니다. 접으면 본문이 창 너비를 모두 씁니다.
- **테마 전환**: 버튼을 누를 때마다 시스템 설정 → 라이트 → 다크 순서로 바뀝니다. 처음에는 시스템 설정을 따릅니다.
- 사이드바 너비, 접힘 상태, 고른 테마는 앱을 닫으면 사라집니다. 저장 위치가 README의 '아직 정하지 않은 것'(작업 화면 설정의 보관 위치)에 해당해 저장하지 않았습니다.
- 창 제목 줄은 OS 기본 제목 줄을 그대로 씁니다.

## 시작 화면

폴더를 열지 않았고 열린 문서도 없을 때입니다(T-022).

```
┌──────────────────────────────────────────────────────────────────┐
│ [◧]                                                          [◐] │
├───────────────┬──────────────────────────────────────────────────┤
│               ┃                                                  │
│ 열린 폴더가    ┃                                                  │
│ 없습니다.      ┃              [ 새 임시 메모 ]   ⌘N               │
│               ┃              [ 폴더 열기    ]   ⌘⇧O              │
│ [폴더 열기]    ┃                                                  │
│               ┃                                                  │
└───────────────┴──────────────────────────────────────────────────┘
```

- 본문 가운데에 두 동작과 단축키 안내를 둡니다. '새 임시 메모'가 주 동작입니다.
- 폴더가 없으므로 워크스페이스 탭은 보이지 않습니다.
- 사이드바는 빈 상태 안내와 '폴더 열기'를 보여 줍니다. 뼈대는 다른 화면과 같게 유지합니다.

## 폴더를 연 상태

```
┌──────────────────────────────────────────────────────────────────┐
│ [◧] ▏네트워크▕  데이터베이스   [+]                            [◐] │
├───────────────┬──────────────────────────────────────────────────┤
│ 공부           ┃ TCP 혼잡 제어.md                         [원문]  │
│ ▾ 네트워크     ┃──────────────────────────────────────────────────│
│   · TCP 혼잡…  ┃                                                  │
│   · OSI 7계층  ┃  # TCP 혼잡 제어                                 │
│ ▸ 데이터베이스  ┃                                                  │
│   메모.txt     ┃  느린 시작과 혼잡 회피 …                          │
│               ┃                                                  │
└───────────────┴──────────────────────────────────────────────────┘
```

- 사이드바 맨 위에 폴더 이름, 그 아래에 파일과 하위 폴더 목록(T-023). 지금 포커스된 영역에 열린 문서가 목록에서 선택 상태로 보입니다.
- 위쪽 줄에 워크스페이스 탭과 새 워크스페이스 버튼 `[+]`(T-041). 활성 탭은 잉크 선으로 표시합니다(DESIGN.md의 '잉크 선 하나' 규칙).
- 본문은 분할 영역 하나입니다. 영역 위쪽에 문서 이름과 그 문서에 대한 동작(Markdown이면 원문 모드 전환)을 두는 머리줄이 있습니다. 저장하지 않은 변경이 있으면 문서 이름 옆에 표시합니다.

## 분할 상태

```
┌──────────────────────────────────────────────────────────────────┐
│ [◧] ▏네트워크▕  데이터베이스   [+]                            [◐] │
├───────────────┬─────────────────────────┬────────────────────────┤
│ 공부           ┃ TCP 혼잡 제어.md  [원문] ┃ OSI 7계층.md    [원문] │
│ ▾ 네트워크     ┃═════════════════════════┃────────────────────────│
│   · TCP 혼잡…  ┃                         ┃                        │
│   · OSI 7계층  ┃  (포커스된 영역)         ├────────────────────────┤
│ ▸ 데이터베이스  ┃                         ┃ 메모.txt               │
│   메모.txt     ┃                         ┃────────────────────────│
│               ┃                         ┃                        │
└───────────────┴─────────────────────────┴────────────────────────┘
```

- 좌우·상하로 나누고 중첩할 수 있습니다(T-040). 영역 사이의 경계선은 사이드바 경계선과 같은 모양과 동작입니다.
- 영역 하나에 문서 하나를 보여 줍니다(T-040의 추측 항목). 영역마다 머리줄이 있습니다.
- **포커스된 영역**은 머리줄 아래 선을 잉크 색 굵은 선(`═`)으로 바꿔 표시합니다. 파일 목록에서 연 파일은 이 영역에 열립니다.
- 같은 문서를 여러 영역에 열 수 있습니다.

## 빈 상태

폴더는 열려 있지만 영역에 문서가 없을 때(새 워크스페이스, 문서를 닫은 영역)입니다.

```
┌──────────────────────────────────────────────────────────────────┐
│ [◧]  네트워크  ▏새 워크스페이스▕  [+]                         [◐] │
├───────────────┬──────────────────────────────────────────────────┤
│ 공부           ┃                                                  │
│ ▸ 네트워크     ┃                                                  │
│ ▸ 데이터베이스  ┃        왼쪽 목록에서 파일을 골라 여세요.          │
│   메모.txt     ┃        새 임시 메모  ⌘N                          │
│               ┃                                                  │
└───────────────┴──────────────────────────────────────────────────┘
```

- 빈 영역은 다음에 할 수 있는 일을 한두 줄로 알려 줍니다. 그림이나 큰 아이콘은 두지 않습니다.
- 분할된 화면에서 빈 영역 하나만 있을 때도 같은 안내를 그 영역 안에 보여 줍니다.
- 폴더가 비어 있으면 사이드바에 "이 폴더에는 파일이 없습니다."와 새 파일 만들기를 보여 줍니다(T-023, T-026).

## 단축키

`⌘S`/`Ctrl+S`(저장)만 README에서 정해진 것이고, `⌘\`/`Ctrl+\`(사이드바)만 T-010에서 구현했습니다. 나머지는 **제안**이며 각 기능 task에서 구현할 때 확정합니다.

| 동작 | macOS | Windows | 상태 | task |
| --- | --- | --- | --- | --- |
| 사이드바 접기·펴기 | `⌘\` | `Ctrl+\` | 구현 | T-010 |
| 저장 | `⌘S` | `Ctrl+S` | README 확정 | T-024 |
| 새 임시 메모 | `⌘N` | `Ctrl+N` | 제안 | T-025 |
| 파일 열기(폴더 밖 포함) | `⌘O` | `Ctrl+O` | 제안 | T-026 |
| 폴더 열기 | `⌘⇧O` | `Ctrl+Shift+O` | 제안 | T-022 |
| 원문 모드 전환 | `⌘E` | `Ctrl+E` | 제안 | T-031 |
| 오른쪽으로 분할 | `⌘D` | `Ctrl+D` | 제안 | T-040 |
| 아래로 분할 | `⌘⇧D` | `Ctrl+Shift+D` | 제안 | T-040 |
| 영역 닫기 | `⌘W` | `Ctrl+W` | 제안 | T-040 |
| 영역 사이 포커스 이동 | `⌘⌥` + 방향키 | `Ctrl+Alt` + 방향키 | 제안 | T-040 |
| 새 워크스페이스 | `⌘T` | `Ctrl+T` | 제안 | T-041 |
| n번째 워크스페이스로 전환 | `⌘1`~`⌘9` | `Ctrl+1`~`Ctrl+9` | 제안 | T-041 |
| 다음·이전 워크스페이스 | `⌃Tab` / `⌃⇧Tab` | `Ctrl+Tab` / `Ctrl+Shift+Tab` | 제안 | T-041 |

정할 때 고려한 점:

- 사이드바에 `⌘B`를 쓰지 않은 것은 Markdown 편집에서 굵게(`⌘B`)와 겹치기 때문입니다.
- `⌘\`는 한글 자판에서 `₩`로 입력되는 키입니다. 글자가 아니라 키 위치로 판정하므로 자판과 무관하게 동작합니다.
- `⌘D`/`Ctrl+D`는 CodeMirror의 기본 동작(다음 일치 항목 선택)과 겹칩니다. T-040에서 분할을 우선할지 정해야 합니다.
- `Ctrl+Alt`+방향키는 일부 Windows 그래픽 드라이버의 화면 회전 단축키와 겹칠 수 있습니다. T-061(Windows 검증)에서 확인이 필요합니다.
- `⌘W`는 macOS에서 창 닫기의 관례입니다. 영역이 하나만 남았을 때의 동작(창을 닫을지, 아무 일도 하지 않을지)은 T-040에서 정합니다.
