# T-005 CI/CD: macOS·Windows에서 check·빌드, 릴리스 초안

- 마일스톤: M0 하네스·개발 환경
- 상태: done
- 검수: 승인 (2026-11-12)
- 의존: T-004
- 담당: 구현자

## 목표

두 대상 OS에서 매 push마다 검증이 돌게 한다.

## 범위

- CI: `develop`, `main` 대상 PR과 푸시마다 macOS·Windows 매트릭스에서 `pnpm check`와 `pnpm tauri build`.
- CD: `main`에 병합되면 두 OS의 설치 파일을 빌드해 GitHub 릴리스 초안에 올린다(서명 없음).
- `develop`, `main` 브랜치 보호 규칙(PR 필수, CI 통과 필수) 설정 방법을 문서화하고 사용자 승인 후 적용한다.
- Rust·pnpm 캐시.

## 범위 밖

- 코드 서명·공증, 자동 업데이트(T-062).

## 완료 기준

- `develop` 대상 PR에서 두 OS 작업이 모두 통과한다.
- 릴리스 워크플로는 문법 검사를 통과하고, 실제 실행은 첫 `main` 병합 때 확인한다.

## 작업 기록

### 2026-11-12 구현자

**결과**

- `develop` 대상 PR에서 두 OS 작업이 모두 통과: **미확인**. 워크플로는 작성했지만 구현자는 푸시할 수 없어 실행해 보지 못했다. 오케스트레이터가 PR에서 확인한다.
- 릴리스 워크플로 문법 검사: **일부만 확인**. YAML 문법은 Prettier(`pnpm exec prettier --check .github`)로 통과했다. GitHub Actions 문법 검사기(`actionlint`)는 설치가 필요해 돌리지 않았다. 실제 실행은 첫 `main` 병합 때 확인한다.

**구성**

- `.github/actions/setup/action.yml`: 두 워크플로가 함께 쓰는 준비 단계. pnpm(`packageManager` 버전) → Node(`.node-version`, pnpm 저장소 캐시) → Rust stable(rustfmt, clippy) → Rust 빌드 캐시(`src-tauri`) → `pnpm install --frozen-lockfile`.
- `.github/workflows/ci.yml`: `develop`·`main` 대상 PR과 푸시에서 macOS·Windows 매트릭스로 `pnpm check` → `pnpm tauri build`. 작업 이름은 `check-build (macos)`, `check-build (windows)`. 권한은 `contents: read`. 같은 PR에 새 커밋이 오면 이전 실행을 취소한다.
- `.github/workflows/release.yml`: `main` 푸시에서 두 OS를 빌드해 설치 파일(`.dmg`, `.msi`, NSIS `.exe`)을 아티팩트로 올리고, 마지막 작업(`draft-release`, ubuntu)이 내려받아 `gh release create --draft`로 초안을 만든다. `contents: write`는 이 마지막 작업에만 있다.
  - 태그는 `src-tauri/tauri.conf.json`의 `version`에서 만든다(`v0.1.0`). 초안이라 git 태그는 게시할 때 생긴다.
  - 같은 태그의 초안이 이미 있으면 지우고 새로 만든다. 같은 태그로 게시된 릴리스가 있으면 덮어쓰지 않고 실패한다(버전을 올리라는 메시지).
  - `pnpm check`는 다시 돌리지 않는다. 같은 푸시에서 CI 워크플로가 돈다.
- 캐시: Rust는 `Swatinem/rust-cache`(키 `tauri`, OS·rustc·`Cargo.lock`별). 저장은 `develop`·`main` 푸시에서만 하고 PR은 읽기만 한다. pnpm은 `actions/setup-node`의 `cache: pnpm`.
- Windows 줄바꿈: 체크아웃 전에 `git config --global core.autocrlf false`를 실행한다. CRLF로 체크아웃되면 `prettier --check`가 실패하기 때문이다.
- 액션 버전은 정확한 릴리스 태그로 고정했다: `actions/checkout@v5.0.0`, `actions/setup-node@v5.0.0`, `pnpm/action-setup@v4.1.0`, `Swatinem/rust-cache@v2.8.0`, `actions/upload-artifact@v4.6.2`, `actions/download-artifact@v5.0.0`. 모든 체크아웃은 `persist-credentials: false`.

**검증**

- `pnpm check` → 성공. Prettier 통과(`.github`의 YAML 포함), Vitest 3개, cargo fmt·clippy 경고 없음, cargo test 1개 통과.
- `pnpm exec prettier --check .github` → 성공(YAML 파싱 확인).
- `pnpm tauri build`는 위임 지시에 따라 돌리지 않았다(앱 코드와 빌드 설정을 바꾸지 않음).

**브랜치 보호 규칙 설정 방법(적용하지 않음, 사용자 승인 후 오케스트레이터가 적용)**

CI가 한 번 돈 뒤에 설정한다(필수 검사 이름이 그때 등록된다). `develop`과 `main`에 각각 같은 규칙을 건다.

- 웹: Settings → Branches → Add branch ruleset(또는 Add classic branch protection rule) → 대상 `develop`, `main`.
  - Require a pull request before merging: 켬. 필요한 승인 수 0(혼자 작업하므로 자기 PR을 승인할 수 없다).
  - Require status checks to pass: 켬. `check-build (macos)`, `check-build (windows)` 추가.
  - Block force pushes: 켬. 삭제 제한: 켬.
  - 관리자에게도 적용(Do not allow bypassing): 켜면 저장소 주인도 직접 푸시할 수 없다.
- 명령(`gh`): 아래 내용을 `protection.json`으로 저장하고 브랜치마다 실행한다.

  ```json
  {
    "required_status_checks": {
      "strict": false,
      "contexts": ["check-build (macos)", "check-build (windows)"]
    },
    "enforce_admins": true,
    "required_pull_request_reviews": { "required_approving_review_count": 0 },
    "restrictions": null,
    "allow_force_pushes": false,
    "allow_deletions": false
  }
  ```

  ```sh
  gh api -X PUT repos/{owner}/{repo}/branches/develop/protection --input protection.json
  gh api -X PUT repos/{owner}/{repo}/branches/main/protection --input protection.json
  ```

- `strict: false`는 병합 전에 브랜치를 최신 `develop`으로 맞추라고 요구하지 않는다는 뜻이다. 여러 구현자의 PR이 동시에 열리므로 꺼 두었다.
- 비공개 저장소는 GitHub 무료 요금제에서 브랜치 보호를 쓸 수 없다. 그 경우 규칙이 저장되지 않거나 적용되지 않는다.
- 릴리스 워크플로는 브랜치에 푸시하지 않으므로 이 규칙과 부딪히지 않는다.

**공용 영역 변경**

- `.github/`를 새로 만들었다. 기존 파일은 이 task 파일만 고쳤다. `AGENTS.md`는 고치지 않았다(코드 구조 절에 넣을 내용은 보고에 적음).

**남은 문제**

- 액션 버전 태그를 확인하지 못했다. 원격 조회(`git ls-remote`)가 허용되지 않아 기억하는 태그를 적었다. 태그가 없으면 PR의 첫 실행이 "unable to resolve action"으로 바로 실패하니 그때 고친다. 커밋 SHA 고정이 더 안전하지만 SHA를 조회할 수 없어 하지 않았다. `git ls-remote --tags https://github.com/<owner>/<repo>`로 조회해 `@<sha> # vX.Y.Z` 형태로 바꿀 수 있다.
- Rust 버전은 고정하지 않았다(`stable`). 새 stable에서 clippy 규칙이 늘면 코드 변경 없이 CI가 실패할 수 있다. `rust-toolchain.toml`로 고정할지는 결정이 필요하다.
- 줄바꿈은 워크플로 안에서만 맞췄다. Windows 개발 머신에서도 같은 문제가 생기므로 `.gitattributes`(`* text=auto eol=lf`)를 넣는 편이 낫다(T-061 또는 별도 task).
- macOS 설치 파일은 Apple Silicon용만 만든다(`macos-latest`가 arm64). Intel용이나 유니버설 빌드가 필요한지는 결정이 필요하다.
- 서명이 없어서 내려받은 `.dmg`는 macOS Gatekeeper가, 설치 파일은 Windows SmartScreen이 막는다(T-062 범위).
- 버전이 `package.json`, `src-tauri/Cargo.toml`, `src-tauri/tauri.conf.json` 세 곳에 있다. 릴리스 태그는 `tauri.conf.json`만 본다. 버전을 올리지 않고 `main`에 병합하면, 그 버전이 이미 게시된 경우 릴리스 워크플로가 실패한다.
- `main` 푸시에서는 CI와 릴리스 워크플로가 각각 빌드해서 두 번 빌드한다.
- 러너 이미지는 `macos-latest`, `windows-latest`, `ubuntu-latest`로 두었다(고정하지 않음).
