# T-020 파일 시스템 백엔드

- 마일스톤: M2 파일·문서 코어 (MVP)
- 상태: review
- 검수: 승인 (2026-11-12)
- 의존: T-004
- 담당: 구현자

## 목표

프런트가 쓰는 파일 작업을 Rust 명령으로 제공한다. 사용자 파일을 손상시키지 않는 것이 최우선이다.

## 범위

- `src-tauri/src/fs/` 모듈과 Tauri 명령: 폴더 나열, 텍스트 읽기, 텍스트 쓰기, 파일·폴더 만들기, 이름 변경(이동 포함), 삭제.
- 쓰기는 원자적으로 한다(같은 폴더에 임시 파일을 쓰고 교체). 줄바꿈(CRLF/LF)과 BOM은 받은 내용 그대로 보존한다.
- UTF-8이 아닌 파일은 열지 않고 오류를 돌려준다(잘못 읽어 저장하면 손상되므로).
- 만들기와 이름 변경은 대상이 이미 있으면 덮어쓰지 않고 오류를 돌려준다.
- 삭제는 영구 삭제가 아니라 OS 휴지통으로 보낸다(`trash` crate, 신규 라이브러리).
- 접근 범위: 사용자가 대화상자로 고른 폴더와 파일만 허용 목록에 넣고, 그 밖의 경로는 거부한다. 폴더·파일 선택 대화상자는 `tauri-plugin-dialog`.
- 나열 결과에 종류를 표시한다: `.md`, `.txt`, 확장자 없음(일반 텍스트), 그 외(열 수 없음). 숨김 파일은 제외한다.
- `src/ipc/fs.ts`에 타입 있는 래퍼와 오류 종류(없음, 이미 있음, 권한, 범위 밖, UTF-8 아님, 기타).

## 범위 밖

- 변경 감시(T-052), 검색(T-053), 외부에서 끌어다 놓기(T-043).
- UI.

## 완료 기준

- 각 명령에 임시 폴더를 쓰는 Rust 테스트가 있다.
- 테스트로 확인: 허용 범위 밖 경로 거부, 기존 파일 덮어쓰기 거부, UTF-8 아닌 파일 거부, CRLF·BOM 파일의 읽기→쓰기 후 바이트 동일.
- `pnpm check`가 통과한다.

## 작업 기록

### 2026-11-12 구현자

**결과 (완료 기준별)**

- 각 명령에 임시 폴더를 쓰는 Rust 테스트: 충족. 나열·읽기·쓰기·파일 만들기·폴더 만들기·이름 변경·삭제 모두 `src-tauri/src/fs/ops.rs`의 테스트가 `tempfile::tempdir`로 검사한다. 대화상자 명령 3개는 OS 창이 필요해 테스트가 없고, 그 뒤의 허용 목록 로직(`scope.rs`)만 테스트한다.
- 허용 범위 밖 경로 거부: 충족. 모든 작업에 대해 확인(`..` 경유, 폴더 밖을 가리키는 심볼릭 링크, 상대 경로, 허용된 파일의 옆 파일 포함).
- 기존 파일 덮어쓰기 거부: 충족. 파일·폴더 만들기와 이름 변경이 `alreadyExists`를 돌려주고 기존 내용이 그대로임을 확인.
- UTF-8 아닌 파일 거부: 충족. EUC-KR, UTF-16 파일이 `notUtf8`.
- CRLF·BOM 읽기→쓰기 후 바이트 동일: 충족. BOM+CRLF, CRLF, 줄바꿈 혼합, BOM+LF(끝 줄바꿈 없음) 4가지.
- `pnpm check` 통과: 충족.

**검증**

- `pnpm check`: 통과. Vitest 17개(그중 `src/ipc/fs.test.ts` 14개), Rust 42개(그중 fs 41개) 통과.
- `pnpm tauri build`: 통과. `tokyonight.app`, `tokyonight_0.1.0_aarch64.dmg` 생성.
- 실행하지 않은 것: 빌드된 앱에서 대화상자를 열어 보는 확인, 실제 OS 휴지통으로 보내는 확인(테스트는 `Trash` trait의 대체 구현 사용), Windows에서의 실행.

**구현하면서 정한 것**

- 명령 10개: `fs_pick_folder`, `fs_pick_file`, `fs_pick_save_file`, `fs_list_dir`, `fs_read_text`, `fs_write_text`, `fs_create_file`, `fs_create_folder`, `fs_rename`, `fs_delete`.
- 허용 목록은 Rust 쪽 대화상자 명령만 채운다. 프런트가 임의 경로를 허용 목록에 넣는 명령은 없다. 목록은 앱 실행 중에만 유지된다.
- 저장 대화상자(`fs_pick_save_file`)를 포함했다. 임시 메모의 첫 저장과 T-026의 새 파일이 아직 없는 경로를 허용 목록에 넣어야 해서다.
- 경로는 링크와 `..`을 푼 실제 경로로 비교한다. 허용된 폴더 자체는 이름 변경·삭제 대상이 될 수 없다.
- 쓰기: 이미 있는 파일은 같은 폴더의 `.tokyonight-*.tmp`에 쓰고 동기화한 뒤 교체하며 원래 권한을 유지한다. 읽기 전용 파일은 `permissionDenied`. 아직 없는 파일은 `create_new`로 만든다.
- `tempfile`을 테스트뿐 아니라 원자적 쓰기의 임시 파일에도 쓴다(일반 의존성). `tauri-plugin-fs`는 직접 쓰지 않았다(`std::fs` 사용, dialog 플러그인의 의존성으로만 들어옴).
- 나열은 한 단계만, 폴더 먼저 이름순. 확장자는 대소문자를 가리지 않는다. 숨김은 `.`으로 시작하는 이름과 Windows 숨김 속성.
- 대소문자만 바꾸는 이름 변경(`note.md` → `Note.md`)은 같은 파일이므로 허용한다.
- 공용 영역 변경: `src/ipc/index.ts`에 fs 내보내기 추가, `src-tauri/Cargo.toml`·`Cargo.lock`에 의존성 3개, `src-tauri/src/lib.rs`에 플러그인·상태·명령 등록.

**남은 문제**

- 이름 변경의 덮어쓰기 방지는 '확인 후 변경'이라, 그 사이 다른 프로그램이 같은 이름을 만들면 막지 못한다. 막으려면 OS별 API(`renamex_np`, `renameat2`, `MoveFileExW`)를 부르는 crate가 필요하다.
- `fs_read_text`는 확장자를 검사하지 않는다. UTF-8이면 `unsupported` 종류도 읽힌다. 열 수 있는지는 나열의 `kind`로 프런트가 판단한다.
- 읽은 문자열 맨 앞에 BOM(U+FEFF)이 그대로 들어 있다. 편집기(T-021, T-024)가 이를 화면에 보이지 않게 하면서 저장할 때는 유지해야 한다.
- 허용 목록이 재실행 후 사라지므로, 최근 작업·워크스페이스 복원(T-042, T-054)에는 저장된 경로를 다시 허용하는 방법이 필요하다.
- Windows에서는 실제 경로가 `\\?\C:\...` 형태로 나온다. 화면 표시와 `trash` 동작은 T-061에서 확인이 필요하다.
- macOS에서 `trash::delete`가 Finder 자동화 권한을 요구하는지는 빌드된 앱에서 확인하지 못했다.

### 2026-11-12 오케스트레이터 검증

- `develop`을 병합한 뒤 `pnpm check` 직접 실행: Vitest 17개, Rust 42개 통과.
- 확인하지 못한 것: 빌드된 앱에서의 대화상자와 실제 휴지통 동작, Windows 실행(CI에서 확인).
