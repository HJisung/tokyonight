# TokyoNight (가칭)

로컬 파일을 중심으로 여러 문서를 한 화면에서 편집하고, 작업별로 분할 화면을 전환하는 Windows·macOS 데스크톱 메모 앱을 구상합니다. `tokyonight`는 임시 저장소 이름이며 제품명은 정해지지 않았습니다.

> 현재 단계: 제품 아이디어와 첫 버전 범위를 정리하는 중입니다. 앱 구현, 기술 스택, 상세 설계 및 개발 하네스 규칙은 아직 확정되지 않았습니다.

## 제품 방향

- 빠르고 가벼운 로컬 중심 메모·문서 작업 환경을 목표로 합니다. 실제 성능은 구현 후 측정합니다.
- 옵시디언처럼 폴더의 문서를 관리하고, Herdr처럼 하나의 창 안에서 작업 공간을 전환하고 화면을 분할합니다.
- 노션처럼 서식이 바로 보이는 편집을 기본으로 제공하되 Markdown 문법 입력과 원문 편집을 지원합니다.
- 개인이 인터넷이나 계정 없이 사용하는 경험을 먼저 완성합니다.

## 용어

- **폴더**: 사용자가 컴퓨터에서 열어 온 실제 파일과 하위 폴더의 위치.
- **워크스페이스**: 하나의 폴더에서 사용 목적별로 만든 작업 화면. 각 워크스페이스는 열린 문서와 분할 배치를 따로 기억합니다. 초기 논의에서 `섹션`이라고 부르던 개념입니다.
- **분할 영역**: 워크스페이스 화면을 좌우 또는 상하로 나눈 영역. 각 영역에 문서를 표시합니다.

예: `공부` 폴더 안에서 `네트워크` 워크스페이스와 `데이터베이스` 워크스페이스를 만들고, 상단 탭을 전환하면 각각의 열린 문서와 분할 배치가 바뀝니다. 한 문서를 여러 영역에서 열 수 있고 편집 내용은 일관되게 반영되어야 합니다.

## 첫 버전 범위

### 시작과 파일

- 시작 화면에서 **새 임시 메모** 또는 **폴더 열기**를 선택합니다. 최근에 선택한 작업을 다시 여는 기능도 고려합니다. 정확한 복원 정책은 미정입니다.
- 임시 메모는 폴더를 열지 않아도 바로 작성합니다. 기본은 TXT이며 버튼으로 MD로 바꿀 수 있습니다.
- 저장되지 않은 임시 메모는 `Ctrl+S`(Windows) 또는 `⌘S`(macOS)로 처음 저장할 때 위치와 이름을 선택합니다. 임시 메모의 자동 복구를 목표로 합니다.
- 이름과 위치를 정해 새 `.md` 또는 `.txt` 파일을 바로 만들 수 있습니다. 열린 폴더에서 새 파일을 만드는 것도 지원합니다.
- 폴더에 있는 `.md`, `.txt`, 확장자가 없는 파일을 엽니다. 확장자가 없는 파일은 일반 텍스트로 취급하며 이름을 임의로 바꾸지 않습니다.
- 폴더 밖의 파일도 현재 창의 분할 영역에서 열 수 있습니다. 임시 메모도 폴더 작업 중 함께 열 수 있습니다.
- 외부 파일이나 폴더를 왼쪽 파일 목록의 대상 폴더로 드래그하면 해당 위치에 **복사**합니다. 원본은 유지하며 이동은 별도 선택으로 제공합니다. 이름 충돌 시 덮어쓰기 전에 사용자에게 처리 방법을 묻습니다.

### 문서 편집

- Markdown은 서식이 즉시 보이는 편집이 기본이고, 원문을 직접 보고 수정하는 모드로 전환합니다.
- TXT와 확장자가 없는 파일은 일반 텍스트로 편집합니다.
- 제목, 문단, 목록, 체크리스트, 인용문, 코드 블록, 링크, 기본 표와 각주를 지원합니다. 표는 기본 행·열과 셀 편집부터 시작합니다.
- 각주는 문서 내용의 일부로 본문에 표시하고 문서 아래에서 확인합니다. Markdown 호환 각주 문법을 사용하는 방향을 검토합니다.
- 기존 Markdown의 지원하지 않는 내용을 모드 전환이나 저장 과정에서 조용히 잃지 않도록 합니다. 구체적인 보존 방식과 지원 범위는 설계·검증이 필요합니다.

### 작업 화면과 저장

- 왼쪽에서 파일과 폴더를 탐색·생성·이름 변경·정리합니다.
- 워크스페이스는 위쪽 탭으로 전환합니다. 각 탭은 열린 문서와 좌우·상하 분할 배치를 독립적으로 기억합니다.
- 분할 영역의 크기를 조절하거나 닫고, 같은 문서 또는 여러 문서를 나란히 볼 수 있습니다.
- 작업 내용을 자동 저장하고, 앱 재실행 시 작업 상태와 임시 메모를 복원하는 것을 목표로 합니다.
- 외부 프로그램의 파일 변경을 감지하고, 충돌이 발생하면 어느 한쪽을 무심코 덮어쓰지 않도록 처리합니다.
- 열린 폴더에서 파일 이름과 문서 내용을 검색합니다.

## 이후에 고려할 기능

- 선택한 텍스트나 문단에 연결하는 피그마식 개인 댓글, 댓글 모아 보기 및 해결 상태.
- 댓글의 작성자·답글·동기화 등 여러 사람의 협업 확장. 첫 버전에서 계정, 서버 또는 실시간 협업은 만들지 않습니다.
- 복잡한 표 편집, Word 직접 편집, 노션식 데이터베이스 및 AI 기능은 첫 버전 범위에 포함하지 않았습니다.

각주는 문서에 포함할 출처·보충 설명이고, 댓글은 나중에 추가할 별도의 의견·작업 메모입니다.

## 아직 정하지 않은 것

- 데스크톱 프레임워크, 편집기 라이브러리, 프로그래밍 언어 등 기술 스택.
- Markdown 원문과 시각 편집 간의 변환 및 미지원 문법의 보존 방식. MDX는 후보 중 하나일 뿐 필수 조건이 아닙니다.
- 작업 화면 설정과 임시 메모 복구 데이터를 보관하는 구체적 위치와 형식.
- 외부 파일 변경 충돌, 파일 이동·이름 충돌, 임시 메모 복원의 세부 동작.
- 최근 작업을 언제부터 제공할지와 시작 시 자동으로 여는 정책.
- 성능 목표 수치, 테스트 전략, Windows·macOS 빌드·배포 방식.
- 개발 하네스 규칙과 작업 위임·검증 절차. 추후 별도로 정합니다.

## 개발 방식과 다음 단계

- 사용자는 대략적인 작업을 전달하고, 에이전트가 목표·범위·완료 기준을 구체화해 Herdr 분할 pane의 다른 에이전트에게 작업을 위임하는 방식을 원합니다. Herdr 제어는 해당 세션의 접근 권한과 환경을 확인한 후 진행합니다.
- 먼저 제품 범위와 화면 구성을 계속 확정하고, 이후 설계·기술 선택·하네스 규칙을 정리합니다. 현재 저장소에는 앱 코드가 없습니다.
- 화면 시안은 로컬 `.superpowers/` 아래의 임시 브레인스토밍 자료이며 저장소에는 포함하지 않습니다. 확정된 결정은 이 문서 또는 이후 설계 문서에 남깁니다.
